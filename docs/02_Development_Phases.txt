Security:  Four rules in every phase (guide A3b): the RUN_KEY is never
           published; no real key in the web app; Claude Code cannot read
           .env and treats scraped data as untrusted; secret scan before
           every commit. The code is PUBLIC on GitHub - that is why the
           scan matters.
Costs:     Only the Anthropic API and Apify are paid. Hosting is free:
           Render Free web service + Neon Free + GitHub (Actions, Pages);
           no payment method on any of them.

Rules
  - Each phase ends with something you can SEE and TEST and leaves the
    product working.
  - Never start a phase until the previous exit test passes.
  - Deploy on Day 1. Push to GitHub once or twice a day: every push
    redeploys the Render service and interrupts a live run.
  - Behind schedule? Apply the CUT ORDER (bottom of this file) at once.
  - Solo-builder rule: keep 60-90 minutes of every day unscheduled. If a
    day has no slack left by mid-afternoon, cut then, not at night.
  - Numbers (limits, budgets, scoring weights) live in config/*.yaml;
    if this plan and config disagree, config wins.

================================================================================
 PHASE 1 - FOUNDATIONS, TOOLS & DEPLOYMENT                 (Day 1)
================================================================================

GOAL
  A deployed skeleton and a set of collection TOOLS that each fetch public
  discourse, clean it (privacy, dates, duplicates, spam, relevance) and
  return a short summary - ready for the agent to call tomorrow.

SCOPE
  1.1 Backend skeleton, config (models.yaml, modes.yaml), doctor command
  1.2 Pack schema 1.0 as Pydantic models; JSON Schema + generated
      docs/SCHEMA.md; database tables (Neon; SQLite in tests)
  1.3 Deploy skeleton to a Render Free web service (Docker, auto-deploy
      from GitHub); /ping endpoint and the keepalive workflow
  1.4 Source catalog (actors verified live, fallbacks, chained comment
      actors)
  1.5 The cleaning chain used inside every tool: normalise, hash authors,
      redact, dates + window, de-duplicate, spam, relevance (Haiku);
      posts under 4 words kept as short_form, never dropped for length
  1.6 Tools: search_reddit, search_tiktok, search_youtube, web_search,
      fetch_and_segment, get_trends (+ search_instagram if its actor
      verifies), coverage_report; fixtures and contract tests; each
      tool's measured latency written into its description
  1.7 CLI: tool <name> "<target>" -> prints the summary the agent will see
  1.8 Quote-link test: text-fragment links built from original, PII-free
      anchor words land on the right post on 3 real Dutch and 3 real
      German forum pages, including one redacted quote (PRD DH12)

TANGIBLE OUTCOME
  - https://signal-<id>.onrender.com shows "SIGNAL"; /health and /ping ok.
  - tool search_reddit "r/MealPrepSunday" prints: collected 40, kept 33,
    relevant 71%, new terms [...], 3 samples, budget left.
  - tool fetch_and_segment on a Dutch forum thread prints word-for-word
    posts with several different author hashes and no names.

EXIT TEST
  [ ] Claude Code is refused when asked to read .env
  [ ] gitleaks blocks a test commit with a fake key
  [ ] Public URL and /health ok; data survives a manual redeploy (Neon)
  [ ] /ping never touches the database; the keepalive workflow runs every
      10 minutes; Render shows instance type "Free" and no payment method
  [ ] docs/SCHEMA.md generated; enums lowercase
  [ ] Every tool works on a real call and on its fixture; tests pass
      without spending money
  [ ] No raw usernames anywhere (Apify, web pages and the 24 h cache);
      author_hash present
  [ ] A date table test (en/nl/de, incl. relative dates) passes; posts
      outside the window are dropped
  [ ] A second identical call within 24 h is cached
  [ ] A 2-word comment ("girl dinner fr") is kept with short_form = true
  [ ] Quote links land on the right post on 3 NL + 3 DE real pages,
      including one redacted quote
  [ ] Every tool description states its measured latency

CUT LINE
  A broken actor with no fallback -> drop that tool and record it as a
  blind spot. Instagram is the first thing to drop.


================================================================================
 PHASE 2 - THE AGENT LOOP                                  (Day 2)
================================================================================

GOAL
  The agent decides where to listen, adapts to what it finds, explains
  every move, and stays inside hard limits - producing a clean corpus.

SCOPE
  2.1 LLM client (two roles, structured output with retry, untrusted
      wrapper, cost tracking, budgets, fake mode)
  2.2 Interpret + plan in one call (with the single clarifying question)
  2.3 Orchestrator + job model: run stages, events written to the events
      table, stop -> partial; runs queued in Neon and claimed by a worker
      in the same process; interrupted runs resumed once; peak memory
      logged (guide B13)
  2.4 The agent loop: tool definitions, system prompt, limits enforced in
      tools, finish() validation, decision log, concurrent tool calls
      (max 3), crash fallback and low-evidence top-up (PRD 8.6)
  2.5 Recorded transcripts for fake mode (so tests and the keyless local
      run replay real agent decisions for free)
  2.6 CLI: research "<brief>" --mode quick|standard
  2.7 Only if the memory test fails: Modal worker (guide Step 2.6, B14)

TANGIBLE OUTCOME
  research "heat pumps for homeowners in Germany" --mode quick prints:
    PLAN  market=DE languages=[de] questions=6 start=[web_forums, youtube,
          reddit:r/de]
    CALL  web_search "Wärmepumpe Erfahrungen Forum" (DE)
          reason: German homeowners discuss installs in forums
          -> 9 threads (haustechnikdialog.de, ...)
    CALL  fetch_and_segment 3 threads -> kept 84, relevant 78%
    CALL  search_reddit "r/de Wärmepumpe" -> relevant 21%
    CALL  coverage_report -> Q3 subsidy confusion: 2 docs
    CALL  web_search "BEG Förderung Wärmepumpe Probleme"
          reason: Q3 under-served
    ...
    FINISH kept: web_forums, youtube | dropped: reddit:r/de (21% relevant)
           gaps: little TikTok discussion for this audience
    CLEAN collected 390 | duplicates 44 | spam 12 | out of window 31 |
          kept 247 | COST Apify $0.90 | Anthropic $0.60

EXIT TEST
  [ ] All four eval briefs produce clearly different plans and agent
      paths (they share < 50% of source units)
  [ ] NL brief: Dutch queries and Dutch communities; DE brief: German
      forums/reviews and German queries; Gen Z: TikTok, Reddit, YouTube
  [ ] Every tool call has a specific reason in the decision log
  [ ] At least one source dropped with a concrete reason on a real run
  [ ] Limits hold: a test with a tiny budget stops cleanly; finish()
      without a fresh coverage_report is refused
  [ ] Fallback: a forced loop error runs the untried starting-plan units
      and logs it; a low-evidence finish tops up from KEPT units only - a
      dropped unit is never called again
  [ ] Two tool_use blocks in one turn run concurrently (their
      timestamps overlap in the run log)
  [ ] "snacks" triggers exactly one clarifying question
  [ ] Spot-check 30 kept docs: >= 60% relevant
  [ ] Quick run within its time and cost caps
  [ ] MEMORY: both Standard runs peak below 400 MB (peak_mem_mb)
  [ ] Killing the process after collection and restarting resumes the
      run from its saved corpus; a refreshed live view misses no events

CUT LINE
  If the loop is unreliable by evening: switch to the research-director
  fallback - code calls the SAME tools in the plan's order, then one
  Sonnet call reviews coverage and picks up to 3 follow-up calls with
  reasons. Same tools, same logs; less freedom.
  If the memory test fails after trimming the biggest stages: move the
  worker to Modal (guide Step 2.6; ~2 h, free credits, no card). The
  public URL and all endpoints stay on Render.


================================================================================
 PHASE 3 - THE PACK ENGINE                                 (Days 3-4)
================================================================================

GOAL
  Turn the corpus into a grounded, verified Context Pack with a playbook a
  marketer would use tomorrow, in every format people and agents need.

SCOPE
  Day 3
  3.1 Extraction (Haiku batches): needs, pains, objections, questions,
      unanswered questions, brands, verbatim phrases, stance, emotion,
      humour, code-switching, occasions, research questions, translation
  3.2 Clustering (one Sonnet call) + membership check (Haiku) + code
      metrics: counts, strength, emotion mix, platform-lens stats,
      momentum / new-in-30-days, what performs, opportunity scores
      (formulas in PRD 5.4-5.5, weights in config/scoring.yaml;
      short_form posts never counted)
  3.3 Generic baseline + synthesis (2 calls by layer group; a 3rd only
      on overflow), each item tied to a cluster
  3.4 Verification (substring + entailment), confidence, safe_to_assert
  Day 4
  3.5 Playbook call (do first, channel plan, hooks, creative brief,
      objections, keywords, targets, this week) + compliance by category
      + guardrails + instructions_for_agents + snapshot + digest +
      schema validation
  3.6 Exports: JSON, Markdown, prompt block, SKILL (zip). Excel is P1.
  3.7 API (/api/v1), SSE events, one MCP server (same read rule as
      REST), run key + spend cap + one-run-at-a-time guard with a FIFO
      queue (max 3 waiting); featured packs (2 flagships)
  No evening work on Day 4: leftover time is slack for 3.5-3.7.

TANGIBLE OUTCOME
  For the NL snack brief: brief.md reads like a one-page brief with do
  first, five truths, generic-vs-found, channels, tensions with Dutch
  quotes, hooks and compliance flags. Unzip the skill, drop it into
  Claude, ask for "three TikTok hooks for our new snack" - Claude uses
  the audience's words without being told to.

EXIT TEST
  [ ] Pack validates against the schema
  [ ] Quote groundedness 100%; a planted fake quote is removed
  [ ] Every item's evidence belongs to its cluster; counts change when a
      test changes cluster members (model text cannot change them)
  [ ] Some items in each flagship pack reach strong; safe_to_assert only
      on strong + observed + verified
  [ ] Minimum content bar met, or thin-evidence notice shown
  [ ] Compliance: a food health claim and a heat-pump savings/green claim
      both get flagged with the right category
  [ ] Brand voice changes hooks and plan, not evidence or claims
  [ ] Skill zip installs in Claude and is used; SKILL.md body
      <= ~2,000 tokens
  [ ] Prompt block <= 1,800 tokens; digest <= 500 tokens
  [ ] Confidence labels reproduce the two PRD 5.4 worked examples in a
      unit test; opportunity items show their four components
  [ ] short_form posts appear in the lexicon but never in counts
  [ ] A second run request is queued with a position, not refused
  [ ] MCP: public read tools work without a key; create needs the key
  [ ] Standard run <= ~12 min within its cap; 2 flagship packs featured

CUT LINE
  Keep: themes, tensions, lexicon, objections, hooks, creative brief, do
  first, channel plan, verification, cluster counts, blind spots, skill
  export. Simplify: platform lens as one paragraph per platform; white
  space from unanswered questions only; competitors without tone.

SCOPE

  4.4 Pack page (all sections, sticky nav, filters, badges with counts),
      evidence drawer, View as agent, Handoff panel, Method section
  4.5 States (incl. queued), keyboard pass, print / save-as-PDF
      stylesheet, one end-to-end test; /evals placeholder; production
      build; deploy

TANGIBLE OUTCOME
  Open a featured pack -> Summary -> a tension -> real quotes with links
  -> View as agent -> same IDs -> Handoff -> download the skill. Enter the
  run key, type a brief, watch the agent's moves appear live.

EXIT TEST
  [ ] Full flow works on the public URL for a featured pack AND a live
      Quick run
  [ ] Every claim opens the drawer; every quote link lands on the post
      (permalink or text fragment)
  [ ] Theatre shows each tool call with its reason; Method lists dropped
      sources with reasons
  [ ] Confidence readable in greyscale; badges show counts
  [ ] Prompt block and skill reachable in <= 2 clicks from the pack page
  [ ] Without the run key, starting a run is refused politely; the key

  [ ] The run key is masked in the field and never visible on screen
  [ ] Print / Save as PDF of a pack gives a clean brief (no nav, buttons

CUT LINE
